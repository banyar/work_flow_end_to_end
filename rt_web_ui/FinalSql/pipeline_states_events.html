Pipeline State Reference

Remote-resolve pipeline run တစ်ခုက ဖြတ်သွားနိုင်တဲ့ state အားလုံးနဲ့ pipeline_run_events ထဲ ရေးတဲ့ event အားလုံးကို code (rt_web_ui၊ noc_automation၊ rtutil၊ rtdatacore) ကနေ တိုက်ရိုက် စုထားတဲ့ စာရင်းပါ။ Database table တွေကို ဖတ်တဲ့အခါ၊ run တစ်ခု ဘယ်မှာ ပိတ်နေလဲ ရှာတဲ့အခါ သုံးပါ။

Table ၃ ခု ဘယ်လို ဆက်စပ်လဲ

pipeline_runs

Run တစ်ခုကို row တစ်ခု။ current_state မှာ အခု ဘယ်မှာ ရောက်နေလဲ၊ last_state_reason မှာ ဘာကြောင့်လဲ၊ completed_at မှာ terminal state ရောက်တဲ့အချိန်။

pipeline_run_events

Append-only history။ State ပြောင်းတိုင်း (from_state → to_state) နဲ့ state မပြောင်းတဲ့ အဆင့်တွေ (from_state = to_state) ကို row တစ်ခုစီ ရေးပါတယ်။ ဘယ်လို ရောက်လာခဲ့လဲ။

retry_jobs

Node-RED fetch ဒါမှမဟုတ် Kafka publish fail ဖြစ်ရင် Retry Worker နောက်မှ ပြန်လုပ်မယ့် job။ Retry လုပ်နေတဲ့ job ကို pipeline_runs.active_retry_job_id က ညွှန်ပါတယ်။

ချိတ်ဆက်ပုံ: table ၃ ခုလုံး run_id (UUID, CHAR(36)) နဲ့ ဆက်ပါတယ်။ Foreign key မထားပါ၊ application က ထိန်းပါတယ်။
